## 指示内容２ 生成物の条件定義

### (1)以下の内容でPythonのWebアプリを生成すること
- Python 3.12 以上、Django 6.1、psycopg 3(psycopg[binary])
  - Django プロジェクト名："config"、アプリ名："app"
  - 開発環境：VSCode(venv を作成して利用)
  - `DBMS:PostgreSQL 18.4`

### (2)プロジェクトの構成
- settings.py はローカル開発用の通常設定だけを書く。STATIC_ROOT、FORCE_SCRIPT_NAME、本番用の切り替えは書かない
- INSTALLED_APPS は django.contrib.sessions、django.contrib.staticfiles、app の3つだけにする(auth・admin・contenttypes・messages は入れない)
- MIDDLEWARE は SecurityMiddleware、SessionMiddleware、CommonMiddleware、CsrfViewMiddleware、XFrameOptionsMiddleware とする
- `LANGUAGE_CODE='ja'、TIME_ZONE='Asia/Tokyo'、DEBUG=True、ALLOWED_HOSTS=['127.0.0.1', 'localhost']`
- テンプレートは templates/app/ 配下に置き、{% url %} と {% static %} を使う
- style.css と logo.svg は static/ にコピーする
- フォーム(ログイン・ログアウト)には {% csrf_token %} を入れる
- パスの比較が必要な場合は request.path_info を使う
- requirements.txt を作成する(gunicorn は含めない)。pip を実行できない環境では次の2行を書く
  - `Django>=6.1,<6.2`
  - `psycopg[binary]>=3.2`

> **補足**  
> auth 系を入れないため、Django 標準のログイン機能は使わずセッションで判定する。  
> 本番設定は AWS 側の settings_prod.py が上書きする  

### (3)画面の URL
- GET /login … ログイン画面を表示、POST /login … ログイン認証
- GET / … /login へリダイレクト
- GET /products … 商品一覧画面
- GET /orders?code=商品コード … 注文情報詳細画面
- POST /logout … セッションを破棄し /login へリダイレクト
- ログイン中かどうかはセッションのキー "loginUser" の有無で判定する

### (4)DBの接続情報と SECRET_KEY は環境変数から読み込むこと(settings.py に値を直書きしない)
- DB_HOST、DB_PORT、DB_NAME、DB_USER、DB_PASSWORD、DJANGO_SECRET_KEY
- ローカルでの値
  - `DB_HOST=localhost`
  - `DB_PORT=5432`
  - `DB_NAME=myappdb`
  - `DB_USER=myapp`
  - `DB_PASSWORD=1234`

> **補足**  
> コマンドプロンプト(cmd)での設定例:  
> `set DB_HOST=localhost`  
> `set DB_PORT=5432`  
> `set DB_NAME=myappdb`  
> `set DB_USER=myapp`  
> `set DB_PASSWORD=1234`  
> `set DJANGO_SECRET_KEY=任意の長い文字列`  
> (= の前後に空白を入れない)  
> `PowerShell の場合:`  
> `$env:DB_HOST="localhost" のように書く`  

### (5)テーブル定義と初期データは以下の SQL ファイルを参照
- テーブル定義書（myappdb）.sql
- DDL(CREATE TABLE)と初期データ(INSERT)が書かれている。テーブル名・列名・型・主キーはこのファイルのとおりにする
- プログラムからはテーブルの作成・データ投入・削除(DDL/DML)を実行しない。データの読み取り(SELECT)だけを行う
- [廃番商品]テーブルは本アプリでは使わない
- 業務テーブルは既存。モデルは managed = False とし、db_table と db_column に日本語のテーブル名・列名を指定する
- [注文テーブル]の主キーは models.CompositePrimaryKey("注文日", "注文番号", "注文枝番") で定義する
- settings.py に MIGRATION_MODULES = {'app': None} を書く
- 集計が必要な商品一覧は django.db.connection の cursor で SQL を実行してよい(値はプレースホルダ %s で渡す)

> **補足**  
> python manage.py migrate で作られるのは django_session と django_migrations だけ。makemigrations は実行しない  
> このSQLは各テーブルを DROP TABLE … CASCADE で削除して作り直す。実行するとデータが初期化されるため、研修用DB(myappdb)以外では実行しない。  
> アプリを動かす前に、DB で実行してテーブルと初期データを作っておく(A5M2 など)  


## 指示内容3 ログイン画面

### (1)以下の内容で「ログイン画面」を生成すること
- 画面レイアウトは以下に準拠
  - `login.html`
  - login.htmlから参照されるファイルも参照すること

### (2)ログイン時の認証を組み込む

### (2-1)ログイン認証用アイテム
- ”ユーザ名”
  - ”パスワード”

### (2-2)ログイン時の認証方法
- [ユーザー情報]テーブルの値との一致を認証する
  - ”ユーザ名”：[ユーザー情報].eメール と値が一致すること
  - ”パスワード”：入力値を UTF-8 のバイト列にして SHA-256 でハッシュ化し、小文字16進数64桁の文字列にしたものが [ユーザー情報].パスワード と一致すること(ソルトなし)
- ハッシュ化には hashlib.sha256(password.encode('utf-8')).hexdigest() を使う
- Django の make_password / check_password は使わない

> **補足**  
> Java 版と同じ方式のため、同じユーザー(user@example.com)でそのままログインできる(相互ログイン)。  
> 確認用ユーザーはテーブル定義書(sql)の初期データで登録済み。  
> ユーザ名:user@example.com  
> パスワード:1234(DB には SHA-256 のハッシュ値が入っている)  

### (2-3)ログイン認証に成功：
- セッションの "loginUser" に eメール を保存し、「商品一覧画面」(/products)へリダイレクト

### (2-4)ログイン認証に失敗：
- 再度ログイン画面を表示

> **補足**  
> ログイン認証失敗時には以下のメッセージをメッセージエリアに表示(html に準拠)  
> 「ユーザ名またはパスワードが正しくありません。」

### (4)「商品一覧情報」の生成

### (4-1)[商品テーブル]は全件取り込む

### (4-2)[商品テーブル]は[注文テーブル]とLEFT JOINする(結合キー：”商品コード”）

### (5)「商品一覧画面」への情報セット

### (5-1)(4)で生成した「商品一覧情報」から画面に表示する項目をすべてセットする
- ”商品コード”の昇順で表示
- ”注文状況”には、[注文テーブル]に情報が存在する商品について ”注文日”と”注文番号”の組の種類数を”件数”として「注文(n 件)」の形式で表示する
- 件数は次の式で数える(注文が無い商品は 0 件になる)
  - `COUNT(DISTINCT (o.注文日, o.注文番号)) FILTER (WHERE o.注文番号 IS NOT NULL)`
- 件数が 0 件の商品は「注文なし」と表示する
- 各カラムの表示形式は html に準拠する(カンマ区切りなどの整形は view かカスタムテンプレートフィルタで行う)

> **補足**  
> 主キーに注文日が含まれ、別の日に同じ注文番号があり得るため、注文日と注文番号の組で数える。  
> django.contrib.humanize は INSTALLED_APPS に入れない  
> LEFT JOIN で注文が無い商品は (NULL, NULL) の組になり、FILTER を付けないと 1 件と数えられてしまう  

### (5-2)”注文状況”のカラムには「注文情報詳細画面」(/orders?code=商品コード)へのリンクを張る
- ”注文”情報が存在しない”商品”の”注文状況”は「注文なし」と表示しリンクは張らない(html に準拠)
- ”関連商品コード”が無い場合は「―」と表示する(html に準拠)
