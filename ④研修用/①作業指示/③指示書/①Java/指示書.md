## 指示内容２ 生成物の条件定義

### (1)以下の内容でJavaアプリを生成すること
- Maven の war プロジェクト(Eclipse にインポートして動的Webプロジェクトとして扱う)
  - `Java 25 (OpenJDK), Servlet / JSP, Apache Tomcat 11`
  - プロジェクト名："Sample01"
  - `DBMS:PostgreSQL 18.4`

### (2)プロジェクトの構成
- `maven.compiler.release=25`
- Servlet API は jakarta.servlet を使う(jakarta.servlet-api 6.1、scope=provided)。javax.servlet は使わない
- JDBC ドライバは postgresql 42.7.13 を依存に含め、WAR に同梱する
- JSP の一覧表示には JSTL 3.0 を使う(jakarta.servlet.jsp.jstl-api と org.glassfish.web:jakarta.servlet.jsp.jstl を依存に含める)
- db.properties は src/main/resources に置き、クラスパスから読み込む
- DB 接続の前に Class.forName(db.driver) を呼ぶ
- JSP は src/main/webapp/WEB-INF/jsp 配下に置き、サーブレット経由でのみ表示する
- style.css と logo.svg は src/main/webapp にコピーする
- リンクとリダイレクトには request.getContextPath() を付ける
- リクエストとレスポンスの文字コードは UTF-8 とする

> **補足**  
> Tomcat 11 は jakarta 名前空間のみ対応。  
> WAR 同梱のドライバは自動登録されないことがあるため Class.forName を明示する  

### (3)画面の URL(サーブレットのマッピング)
- GET /login … ログイン画面を表示、POST /login … ログイン認証(ウェルカムページも /login)
- GET /products … 商品一覧画面
- GET /orders?code=商品コード … 注文情報詳細画面
- POST /logout … セッションを破棄し /login へリダイレクト
- ログイン中かどうかはセッション属性 "loginUser" の有無で判定する

### (4)DBの接続情報はプロパティファイル(db.properties)を利用すること
- db.properties に記録する内容
  - `db.url=jdbc:postgresql://localhost:5432/myappdb`
  - `db.user=myapp`
  - `db.password=1234`
  - `db.driver=org.postgresql.Driver`

> **補足**  
> db.password は WAR に含まれるため、AWS へデプロイする前に書き換える(フェーズ②の手順書で案内)  

### (5)テーブル定義と初期データは以下の SQL ファイルを参照
- `②テーブル定義書\テーブル定義書（myappdb）.sql`
- DDL(CREATE TABLE)と初期データ(INSERT)が書かれている。テーブル名・列名・型・主キーはこのファイルのとおりにする
- プログラムからはテーブルの作成・データ投入・削除(DDL/DML)を実行しない。データの読み取り(SELECT)だけを行う
- [廃番商品]テーブルは本アプリでは使わない

> **補足**  
> このSQLは各テーブルを DROP TABLE … CASCADE で削除して作り直す。実行するとデータが初期化されるため、研修用DB(myappdb)以外では実行しない。  
> アプリを動かす前に、DB で実行してテーブルと初期データを作っておく(A5M2 など)  


## 指示内容3 ログイン画面

### (1)以下の内容で「ログイン画面」を生成すること
- 画面レイアウトは以下に準拠
  - `①html\login.html`
  - login.htmlから参照されるファイルも参照すること

### (2)ログイン時の認証を組み込む

### (2-1)ログイン認証用アイテム
- ”ユーザ名”
  - ”パスワード”

### (2-2)ログイン時の認証方法
- [ユーザー情報]テーブルの値との一致を認証する
  - ”ユーザ名”：[ユーザー情報].eメール と値が一致すること
  - ”パスワード”：入力値を UTF-8 のバイト列にして SHA-256 でハッシュ化し、小文字16進数64桁の文字列にしたものが [ユーザー情報].パスワード と一致すること(ソルトなし)
- ハッシュ化には java.security.MessageDigest("SHA-256") を使う
- SQL の値は PreparedStatement のプレースホルダ(?)で渡す

> **補足**  
> 確認用ユーザーはテーブル定義書(sql)の初期データで登録済み。  
> ユーザ名:user@example.com  
> パスワード:1234(DB には SHA-256 のハッシュ値が入っている)  

### (2-3)ログイン認証に成功：
- 「商品一覧画面」(/products)へリダイレクト

### (2-4)ログイン認証に失敗：
- 再度ログイン画面を表示

> **補足**  
> ログイン認証失敗時には以下のメッセージをメッセージエリアに表示(html に準拠)  
> 「ユーザ名またはパスワードが正しくありません。」  


## 指示内容４ 商品一覧画面

### (1)「商品一覧画面」の生成
- 画面レイアウトは以下に準拠
  - `①html\product_list.html`
  - product_list.htmlから参照されるファイルも参照すること

### (2)ログイン認証を経由せずに「商品一覧画面」へ遷移した場合：

### (3)ログアウトボタン
- html に合わせ POST /logout で「商品一覧画面」からログアウトし「ログイン画面」へ遷移する

### (4)「商品一覧情報」の生成
- [商品テーブル]と[注文テーブル]を取り込む

### (4-1)[商品テーブル]は全件取り込む

### (4-2)[商品テーブル]は[注文テーブル]とLEFT JOINする(結合キー：”商品コード”）

### (5)「商品一覧画面」への情報セット

### (5-1)(4)で生成した「商品一覧情報」から画面に表示する項目をすべてセットする
- ”商品コード”の昇順で表示
- ”注文状況”には、[注文テーブル]に情報が存在する商品について ”注文日”と”注文番号”の組の種類数を”件数”として「注文(n 件)」の形式で表示する
- 件数は次の式で数える(注文が無い商品は 0 件になる)
  - `COUNT(DISTINCT (o.注文日, o.注文番号)) FILTER (WHERE o.注文番号 IS NOT NULL)`
- 件数が 0 件の商品は「注文なし」と表示する
- 各カラムの表示形式は html に準拠する

> **補足**  
> 主キーに注文日が含まれ、別の日に同じ注文番号があり得るため、注文日と注文番号の組で数える  
> LEFT JOIN で注文が無い商品は (NULL, NULL) の組になり、FILTER を付けないと 1 件と数えられてしまう  

### (5-2)”注文状況”のカラムには「注文情報詳細画面」(/orders?code=商品コード)へのリンクを張る
- ”注文”情報が存在しない”商品”の”注文状況”は「注文なし」と表示しリンクは張らない(html に準拠)
- ”関連商品コード”が無い場合は「―」と表示する(html に準拠)
